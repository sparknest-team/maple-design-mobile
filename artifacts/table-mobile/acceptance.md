# Maple Table 移动端验收

2026-11-20，以当前工作区的完整 Table 入口为对象。

## 三引擎

移动示例页运行于本地文档服务。Chromium 151.0.7922.34、Firefox 153.0、WebKit 26.5 各通过 3 个场景。每个引擎验证左右冻结列与拆分表头对齐、Tabs 内斜滑、虚拟变高行的展开与回位，并断言自然高度容器能显示行内容。Chromium 使用协议触控验证原生滚动方向；Firefox 和 WebKit 的斜滑覆盖合成触摸事件处理。虚拟行 S-10014 在三个引擎中均滚出渲染窗口，返回后仍展开，纵向位置偏差为 0 CSS px。

从 Maple 仓库运行以下命令可重测已启动的文档站。默认访问 localhost 的 8080 端口，也可用 MAPLE_DOCS_URL 指定其他本地站点。

```sh
node --test scripts/browser/table-mobile.test.mjs
```

三引擎均在已有横向滚动和展开状态下完成 375×900 → 900×375 → 375×900 的视口切换。冻结列持续贴边，表头表体对齐，展开行纵向偏差均为 0 CSS px。

详见 [三引擎日志](three-engines.log)。

## iPhone 模拟器

iPhone 12，iOS 14.5（18E182），Safari 14.1。该运行时在本机可用。开发文档站在这个旧运行时未挂载示例，因此从相同的三个 Vue Demo、组件、主题与样式构建了独立页面，以项目 es2016 目标运行。三引擎测试直接使用移动文档页面。

| 项目 | 修复后的观测 |
| --- | --- |
| 自然高度 | 冻结表示例、Tabs 内表格、虚拟表格的根高度分别为 293、156、323 CSS px。修复前均为 0。 |
| 左右冻结 | 表体横移 145px，表头同步移至 145px。左右冻结列的左边缘分别保持在 17px 和 253px。 |
| 横向为主的斜滑 | XCTest 在销售表格单元格内向左上拖动。表格从 0 移至 150px，页面保持 218px，销售标签仍激活。 |
| 纵向为主的斜滑 | 表格保持 150px，页面从 218 移至 464px，销售标签仍激活。两次触摸均命中表内并产生 trusted 事件。 |
| 展开和回位 | 在卷动高度 540px 展开 S-10014，再向下滚动 2600px，确认原行卸载。回到 540px 后，该行距视口顶部仍为 62px，展开状态及对应追踪号均保留。 |

模拟器复现了 Loading 容器使用百分比高度时表格塌陷的问题。修复使用纵向 flex 传递可用高度，自然高度由内容撑开。另在模拟器上核对了父容器 400px、表格 50% 高度时，表格及其 Loading 容器均为 200px。

XCTest 驱动 iPhone 12 系统旋转，Safari 可用宽度依次为 390、750、390 CSS px。三个状态下左右冻结列边缘误差、表头表体对齐误差均为 0，横向滚动位置始终为 145px。展开的 S-10014 及详情保持可见，该行始终距表体顶部 62px。
